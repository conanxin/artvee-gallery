# Artvee Gallery · Open Source Boundaries

> Why this repository looks the way it does. The data / code split is
> deliberate, and this document is the single source of truth for what
> is and is not shipped as part of an open-source release.

## 1. One-paragraph summary

This repository is a **code, docs, and tiny sample data** project.
All heavy data — original image assets, full metadata archive, generated
thumbnails, runtime logs, local staging, and any nightly build output —
is **regenerated locally by the user** from the scripts we ship. None
of it is tracked in git, none of it is published to the public demo
in full, and none of it should ever appear in a public commit.

## 3. What is **not** in the repository

| Path | Why it is excluded |
| --- | --- |
| `images/` | The downloaded original assets; can be 1 GB+; per-machine |
| `metadata/` | Per-artwork JSON; per-machine |
| `thumbs/256/`, `thumbs/512/` | Generated, regenerable, can be tens of thousands of files |
| `web/data/artworks.json` | Generated gallery index (large) |
| `web/data/gallery_stats.json` | Generated stats (small, but regenerable) |
| `web/data/digests.json` | Generated digest index (regenerable) |
| `dist/` | Regenerable public demo bundle |
| `digests/` | Per-day, regenerable |
| `inbox/`, `index/`, `logs/`, `backups/` | Local-only staging and runtime |
| `*.bak`, `*.bak.*`, `*.swp`, `*.swo`, `*.tmp`, `*.lock`, `*.pid` | Local editing cruft |
| `__pycache__/`, `*.pyc`, `*.pyo`, `.pytest_cache/` | Python build artefacts |
| `.DS_Store`, `Thumbs.db`, `.idea/`, `.vscode/` | OS / editor artefacts |

All of the above is enumerated in `.gitignore` and is enforced by
`scripts/check_open_source_ready.py`.

## 4. Why the public demo is safe to publish

The public demo (`dist/artvee-gallery-public-demo/`, deployed to the
GitHub Pages demo URL) is a **curated subset** of the local gallery,
regenerated by `scripts/export_artvee_gallery_public_demo.py`. It:

- Contains **only** thumbnails (256 / 512 px JPG), never the
  original download (which is typically 1-10 MB per artwork).
- Carries no `/home/`, `~/`, or `hermes-agent` substring (the
  exporter rewrites all local paths to relative `./assets/...`).
- Carries no `inbox/`, `index/`, or `logs/` data.
- Carries no per-artwork download paths from the local machine;
  only the public `source_url` pointing back to artvee.com.
- Carries no API tokens, credentials, or environment variables.

The demo URL is a **separate, opt-in artifact** that the user
produces and deploys themselves. This repository does not include
the demo bundle in the git tree.

## 5. Risk surface — what we actively guard against

The release is checked by `scripts/check_open_source_ready.py`. The
checks are:

1. **Tracked-file inventory** — list every file in the git index.
2. **Generated-data check** — fail if any path starting with
   `images/`, `metadata/`, `thumbs/`, `dist/`, `digests/`, `logs/`,
   `inbox/`, or `web/data/` is tracked (excluding `.gitkeep`).
3. **Path-leak check** — for non-source text files (`.md`, `.json`,
   `.html`, `.css`, `.js`, `.txt`, configs), fail if the file
   contains `/home/`, `~/`, or `hermes-agent`. (Source code is
   exempted because it legitimately mentions these strings in
   defensive checks and design comments.)
4. **Sensitive-keyword check** — across all tracked text files,
   fail on patterns that look like real secrets (e.g.,
   `password\s*=\s*["'][^"']{4,}`). Comments and docstrings
   about *what* the script does to prevent leaks are not flagged.
5. **File-size check** — warn on any tracked file > 1 MB.

The script prints PASS / FAIL with a per-check breakdown and a
non-zero exit on FAIL. It never modifies anything.

## 6. What users get — and what they don't

| User runs | What the user gets on disk |
| --- | --- |
| `git clone` | Source code, docs, examples, UI shell. **No images, no metadata, no thumbnails, no demos, no digests, no logs.** |
| `python3 scripts/build_artvee_gallery.py --mode local` | The shell becomes usable because `web/data/*.json` and `thumbs/` are now populated — **from the user's own `images/` + `metadata/` + `index/`** (which they have to provide). |
| `python3 scripts/export_artvee_gallery_public_demo.py ...` | A deployable static bundle under `dist/`, with the same privacy guarantees as the live demo. |
| `python3 scripts/build_artvee_daily_digest.py ...` | A per-day Markdown + HTML digest, written under `digests/`, also privacy-safe. |
| `bash scripts/artvee_nightly_wrapper.sh batch` | Wraps the above into a cron-friendly chain. Only meaningful if the user has set up their own `inbox/`, `images/`, `metadata/` source archive. |

## 7. Migration note for existing private copies

If you are forking an existing private copy of this project into a
fresh public repository:

1. Run `scripts/check_open_source_ready.py` — it will tell you
   exactly what needs to be cleaned up first.
2. Confirm the wrapper script (`scripts/artvee_nightly_wrapper.sh`)
   uses a path-agnostic `BASE_DIR` (it derives from its own
   location, not `$HOME`).
3. Confirm there are no environment variables holding tokens
   committed anywhere (the readiness check covers this).
4. Initialise a fresh public repository and push only the
   `README.md LICENSE docs examples scripts web .gitignore`
   surface area; do not copy the `images/`, `metadata/`, `thumbs/`,
   `dist/`, `digests/`, `logs/`, `inbox/`, `index/`, `backups/`
   directories across.
